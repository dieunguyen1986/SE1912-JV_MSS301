01Vấn đề Upload File trong Microservices & Claim Check Pattern

Khi mới làm quen với kiến trúc Microservices và Event-Driven (RabbitMQ/Kafka), một sai lầm cực kỳ phổ biến là "nhét" toàn bộ nội dung file (PDF, hình ảnh) dưới dạng Byte Array hoặc chuỗi Base64 vào thẳng bên trong Event Message.

Anti-Pattern (Thực hành xấu)

Message Broker (RabbitMQ) được thiết kế tối ưu cho việc truyền các luồng sự kiện rất nhỏ (vài KB). Việc đính kèm file vài MB vào message sẽ gây ra: (1) Tắc nghẽn mạng nội bộ, (2) Tràn bộ nhớ (OOM) của Broker, và (3) Hệ thống sụp đổ khi có lượng request cao.

Giải pháp: Claim Check Pattern (Gửi đồ - Lấy thẻ)

Thay vì truyền file trực tiếp qua mạng, hệ thống sử dụng một Object Storage dùng chung (như Amazon S3 hoặc MinIO). Pattern này hoạt động giống hệt quy trình "gửi đồ" ở siêu thị:

  1. Bạn mang cái balo to (File CV) tới siêu thị.
  2. Bạn không xách balo đi dạo (Message Broker). Bạn đưa nó cho quầy giữ đồ (Object Storage - MinIO).
  3. Quầy giữ đồ trả cho bạn một chiếc thẻ nhựa nhỏ gọn (Đường dẫn File URL / File ID).
  4. Bạn cầm chiếc thẻ đó truyền đi khắp nơi. Ai có nhiệm vụ xử lý balo của bạn (ví dụ bảo vệ) sẽ cầm chiếc thẻ đó ra quầy giữ đồ để tự lấy balo về.

02Lựa chọn Kiến trúc Upload CV cho TalentHub

Trong hệ thống TalentHub, File CV về mặt nghiệp vụ thuộc quyền sở hữu của candidate-service. Tuy nhiên, hành động "Nộp đơn" lại được gọi tới application-service. Vậy file CV nên đi đường nào?

Chúng ta sử dụng giải pháp chuẩn mực (Best Practice) cho Frontend hiện đại (React/Angular/Vue) bằng cách chia việc Upload thành 2 bước riêng biệt:

Bước Hành động của UI (Frontend) Kết quả nhận được
Bước 1 (Upload) UI gửi file CV gọi API POST /api/candidates/{id}/cvs sang thẳng candidate-service. Service này lưu file vào MinIO. Trả về mã giữ đồ (Ví dụ: fileName = "123-abc.pdf").
Bước 2 (Apply) UI ghép JSON dữ liệu form cùng với cái fileName đó, gửi API POST /api/applications sang application-service. Nộp đơn thành công. Bắt đầu Saga Flow.

Với cách này, application-service chỉ làm việc với text (tên file), giúp hệ thống tách bạch hoàn toàn, không có service nào phải đóng vai trò "người vận chuyển file" tốn kém băng thông.

03Hướng dẫn Tích hợp MinIO (5 Bước)

Dưới đây là các bước để dựng MinIO và viết mã tích hợp vào dự án Spring Boot.

3.1. Bổ sung MinIO vào Docker Compose

Mở file docker-compose.yml của dự án và bổ sung cấu hình sau. Chú ý khai báo volume ở cuối file.

docker-compose.yml
services:
  # ... các service khác ...
  
  minio:
    image: minio/minio:latest
    ports:
      - "9000:9000"     # Cổng API cho Backend Java gọi vào
      - "9001:9001"     # Cổng Web Console UI (Trình duyệt)
    environment:
      MINIO_ROOT_USER: talenthub_admin
      MINIO_ROOT_PASSWORD: talenthub_password
    command: server /data --console-address ":9001"
    volumes:
      - minio_data:/data

# ...
volumes:
  minio_data:

3.2. Thêm Dependency vào Project

Bổ sung thư viện MinIO SDK vào pom.xml của candidate-service (để upload) và cv-parser-service (để download).

pom.xml
<dependency>
    <groupId>io.minio</groupId>
    <artifactId>minio</artifactId>
    <version>8.5.7</version>
</dependency>

3.3. Cấu hình kết nối MinIO

application.yml
minio:
  url: http://localhost:9000
  access-key: talenthub_admin
  secret-key: talenthub_password
  bucket-name: cv-uploads

Tạo một Configuration class để khai báo Bean MinioClient:

MinioConfig.java
@Configuration
public class MinioConfig {

    @Value("${minio.url}") private String url;
    @Value("${minio.access-key}") private String accessKey;
    @Value("${minio.secret-key}") private String secretKey;

    @Bean
    public MinioClient minioClient() {
        return MinioClient.builder()
                .endpoint(url)
                .credentials(accessKey, secretKey)
                .build();
    }
}

3.4. Tạo Upload Service (Tại Candidate Service)

Đây là class chịu trách nhiệm đưa luồng Byte từ API lên Object Storage.

FileStorageService.java (Tại candidate-service)
@Service
@RequiredArgsConstructor
public class FileStorageService {
    
    private final MinioClient minioClient;
    @Value("${minio.bucket-name}")
    private String bucketName;

    public String uploadFile(MultipartFile file) throws Exception {
        // 1. Sinh tên file ngẫu nhiên để tránh trùng tên (uuid_filename.pdf)
        String fileName = UUID.randomUUID().toString() + "_" + file.getOriginalFilename();
        
        // 2. Kiểm tra bucket tồn tại chưa (nếu chưa thì tạo)
        boolean isExist = minioClient.bucketExists(BucketExistsArgs.builder().bucket(bucketName).build());
        if (!isExist) {
            minioClient.makeBucket(MakeBucketArgs.builder().bucket(bucketName).build());
        }

        // 3. Đẩy luồng stream lên MinIO
        minioClient.putObject(
            PutObjectArgs.builder()
                .bucket(bucketName)
                .object(fileName)
                .stream(file.getInputStream(), file.getSize(), -1)
                .contentType(file.getContentType())
                .build()
        );
        
        return fileName; // Trả về mã định danh (Claim Check)
    }
}

3.5. Tải & Xử lý (Tại CV Parser Service)

Khi Saga chạy tới bước kiểm tra CV, hệ thống không nhận File, hệ thống chỉ nhận `fileName`. Worker tại đây sẽ đi lấy file về.

CvMockParserService.java (Tại cv-parser-service)
@Service
@RequiredArgsConstructor
public class CvMockParserService {

    private final MinioClient minioClient;

    public void parseCv(String fileName) throws Exception {
        // Lấy luồng dữ liệu của file từ MinIO về bộ nhớ
        InputStream stream = minioClient.getObject(
            GetObjectArgs.builder()
                .bucket("cv-uploads")
                .object(fileName)
                .build()
        );
        
        // (Chỉ dành cho Mock Demo) Đoạn này giả lập đang đọc nội dung...
        // Thực tế: sẽ đẩy InputStream này cho thư viện Apache Tika hoặc AI Model.
        
        // Nhớ đóng stream sau khi xử lý xong
        stream.close();
    }
}

04Thực hành và Lời khuyên

Lời khuyên kiến trúc (Dành cho Nhóm Trưởng / Senior)

- Việc thao tác với MinIO rất giống nhau ở mọi Service. Để tránh lặp code, bạn hãy tạo một Maven Module chung tên là talenthub-common chứa class MinioConfig và FileStorageService, sau đó cho các service khác include dependency này vào.
- Trong môi trường thực tế, Frontend sẽ gọi API upload thẳng lên S3/MinIO (thông qua Pre-Signed URL) để tiết kiệm cả 1 nhịp chui qua candidate-service. Tuy nhiên, cách làm 2 bước API như Bài này là phổ biến và phù hợp nhất cho sinh viên vừa làm quen với thiết kế Gateway/Microservices.
